# 1.1.16 — 備份、垃圾桶與離線同步的修正

本版沒有新功能，修正一次完整審查找到的問題。

## 備份與還原

- 每份備份快照旁會多一個同名的 `.files/` 資料夾，保存該快照引用的附件。之後在筆記裡刪掉的附件，還原舊快照時也救得回來。
- 快照完整後才以正式名稱出現，中斷的備份不會留下看起來像備份的檔案。同一時間只會有一個備份在執行。
- 筆記仍引用、但已經找不到的附件會讓備份指令印出警告並以結束碼 1 結束。這份快照另存為 `.incomplete.sqlite`，不佔用完整備份的 7 份名額。
- 還原指令多了一步，把快照的附件放回 `files/`。請改用 [DEPLOY.md](../DEPLOY.md) 的新指令。

## 垃圾桶與歷史

- 永久刪除頁面時，另外列在垃圾桶裡的子頁面不再被一起刪掉，之後還原會回到最上層。屬於被刪除資料庫的資料列仍會一併刪除，確認視窗會寫明筆數。
- 資料列還原歷史版本時保留目前的列名。
- 還原歷史前若這裡有存不進裝置的修改會先擋下；還原進行中又有新的輸入時不會被蓋掉，改以版本衝突讓你選擇。

## 區網明文 HTTP

- 修正以 `http://192.168…` 這類網址開啟時，登入前就白畫面的問題。

## 共用

- 父頁面與子頁面分別分享時，只有內層分享才看得到的資料庫不再從「與我共用」消失。
- 最深一層的頁面與資料列，清單列得出來就打得開。

## 離線同步

- 在別人共用的資料庫離線新增資料列並加入附件，恢復連線後不再卡住：附件會等資料列建立後才上傳。
- 筆記不會早於它引用的附件送出，包括同步進行中才加入的附件，以及選擇「以我的內容覆蓋」的情況。選擇覆蓋後若把被拒絕的附件從內文移除，會請你重新選擇。
- 離線加入的附件上傳後計入此裝置的附件快取上限。

## 其他

- 資料庫列表不再把每一列的內文讀進記憶體。
- 註冊邀請碼在處理途中到期時不再被兌換。

## 升級

沒有資料庫結構變更。使用 Docker Compose 部署時，更新至此版本後執行 `docker compose up --build --wait`，並重新執行一次 `cli backup`：1.1.15 及更早版本建立的快照沒有 `.files/` 資料夾。
