# 1.1.0 — 分享筆記：公開連結與站內帳號共用

原本每個帳號的筆記完全隔離；這一版加入分享。使用說明與權限表見 [SHARING.md](../SHARING.md)。新增一個資料庫 migration（`0009_shares`），沒有調整任何依賴版本。

這一版也包含先前沒有單獨發布的 1.0.8（資料庫、留言與附件的離線使用，migration `0008_offline_receipts`），內容見 [1.0.8.md](1.0.8.md)。從 1.0.7 升級會依序套用兩個 migration。

## 新功能

- **公開連結**：頁面可開啟一條不需登入就能閱讀的網址（`/s/…`）。一律唯讀、看不到留言；可隨時關閉，再次開啟會換新網址。
- **與站內帳號共用**：輸入對方的 email，設為「唯讀」或「可編輯」。兩種都能留言與加表情；可編輯者還能修改內文、一般頁面的標題、資料列，並加入附件。
- **可選範圍**：只有此頁面、含子頁面，或連同資料庫。分享資料庫時資料列一定一起開放。
- **與我共用**：別人分享的頁面列在側欄，頁面上方標示擁有者與權限；可自行移除。
- **共用的筆記也能離線**：會與自己的筆記一起下載到裝置；可編輯者可離線修改，連線後同步。
- **留言有作者**：留言與回覆顯示是誰寫的；表情反應每人各自計算並顯示人數。
- **設定 → 分享**：列出你開放給其他人的所有頁面。

## 行為改變

- 表情反應從「這則討論有哪些表情」改為每個人各自的反應。既有的反應視為頁面擁有者的。
- 把頁面移至垃圾桶會關閉它與底下頁面的公開連結；還原後需重新開啟。
- 另一個人修改內文時，被取代的內容會立即留在頁面歷史（不受一般的 10 分鐘間隔限制）。擁有者寫的版本與成員寫的版本分開保留，各 100 份。
- 刪除整則討論：擁有者或發起討論的人才可以。標示已解決：擁有者、可編輯的成員或發起的人。
- 唯讀成員的留言不會改動頁面；黃色標示由各人的畫面依引文找出位置。
- 頁面內容無法由編輯器顯示時不再讓整個頁面失效，會顯示錯誤並可從頁面歷史還原。

## 仍只有擁有者能做

新增子頁面或資料庫、修改資料庫欄位與視圖、圖示與封面、最愛、搬移、複製頁面、頁面歷史、垃圾桶、設定分享。共用的筆記不會出現在對方的搜尋結果。

## 注意事項

- 公開連結的網址就是鑰匙：拿到網址的人都能閱讀範圍內的內容（含之後加進範圍的頁面）。網址不會被搜尋引擎索引，但可能留在瀏覽器或反向代理的紀錄中；懷疑外流時關閉後重新開啟即可換網址。
- 公開連結的讀取依來源位址限流（每分鐘 600 次）。放在反向代理或 tunnel 後面時請設定 `NOTES_TRUST_PROXY=1`（必要時加 `NOTES_CLIENT_IP_HEADER`），否則所有訪客會被視為同一個來源。見 [DEPLOY.md](../DEPLOY.md)。
- 以 email 加入成員會透露該 email 是否已在本站註冊；每個帳號每小時最多嘗試 30 次。
- 沒有即時協作：兩人同時修改同一頁時，後存的人會看到版本衝突，處理方式與自己在兩台裝置上編輯相同。
- 自行撰寫的腳本：`POST /api/files` 可帶表單欄位 `pageId`（在別人分享、且自己可編輯的頁面加入附件）；留言 API 的回應多了作者與每人的表情欄位，原有欄位不變。

## 升級

升級前先使用線上備份：

```sh
docker compose exec app node dist/server/cli.js backup
git pull
docker compose up -d --build --wait
```

migration `0008_offline_receipts`（從 1.0.7 升級時）與 `0009_shares` 會在啟動時自動套用。
