# 1.1.2 — 公開連結與「知道連結的本站帳號」共用一個連結

1.1.1 開啟「知道連結的本站帳號」會顯示頁面網址，開啟公開連結又是另一個網址。這一版改為每個分享只有一個連結：公開連結是主開關，打開後才設定登入的本站帳號可以做什麼。新增一個資料庫 migration（`0011_share_single_link`），沒有調整任何依賴版本。使用說明見 [SHARING.md](../SHARING.md)。

## 變更

- **只有一個連結**：分享視窗只顯示公開連結（`/s/…`），不再顯示頁面網址。
- **公開連結是主開關**：打開後，開關下方才出現「知道連結的本站帳號」選單；公開連結關閉時沒有這個選項。
- **選單的三個選項**：「與未登入相同（只能閱讀）」（預設）、「知道連結的人皆可唯讀」（可留言與加表情）、「知道連結的人皆可編輯」。
- **沒有登入的人不受影響**：用同一個連結仍然只能閱讀，看不到留言。
- **登入的本站帳號**：選單設為唯讀或可編輯時，開啟公開連結會直接進入應用程式內的頁面，依設定的權限使用，並列入側欄「與我共用」、下載到裝置供離線使用。擁有者在分享視窗看得到有哪些帳號開啟過。
- **關閉公開連結**：帳號的設定與透過連結進來的帳號一併失效；再次開啟是新的網址，設定要重新選。把頁面移至垃圾桶也一樣。
- 選單改回「與未登入相同」後，透過連結進來的帳號立即失去權限，公開連結本身不變。

## 與 1.1.1 不同之處

- **只知道頁面網址（`/p/…`）不再有任何權限**，必須登入後開啟過公開連結。1.1.1 中頁面網址可能出現在其他共用頁面的連結裡而被用來開啟，這個途徑已經關閉。
- **不能只開放給本站帳號而不公開**：要讓知道連結的帳號有權限，必須先打開公開連結；不想公開時請用 email 個別指定帳號。
- 擁有者自己與個別指定的成員開啟公開連結時，會被帶到自己原本就能使用的頁面；要看公開版本請用無痕視窗。
- 已經開啟公開連結時再次送出「開啟」不會更換網址；關閉後再開才會換。

## 注意事項

- 「知道連結的人皆可編輯」等於讓本站所有拿到公開連結的帳號都能修改這個頁面（與範圍內的頁面）。被取代的內容會留在頁面歷史，擁有者可以還原。懷疑連結外流時，關閉公開連結再重新開啟即可換網址，先前透過連結進來的帳號也全部失效。
- 登入的帳號開啟公開連結就會被記為「開啟過」，頁面會加入自己的「與我共用」。

## 升級

升級前先使用線上備份：

```sh
docker compose exec app node dist/server/cli.js backup
git pull
docker compose up -d --build --wait
```

migration `0011_share_single_link` 會在啟動時自動套用：1.1.1 中「沒有開啟公開連結、卻開放給知道連結的帳號」的分享，會清除該設定與開啟紀錄（不會替擁有者開啟公開連結），需要時請重新開啟公開連結並設定。已經同時開啟公開連結的分享不受影響；以 email 個別指定的成員不受影響。
