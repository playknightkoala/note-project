# 1.1.7 — 更新改為必要、版號可看更新紀錄、選取文字後右鍵恢復

這一版調整更新的流程：有新版時先儲存再提示，而且一律要更新；左下角的版號改為打開更新紀錄。另外修正電腦上選取文字後右鍵沒有反應。只改前端與更新資訊清單的位置，沒有資料庫 migration，沒有調整任何依賴版本。

## 變更

- **先儲存、再出現更新視窗**：偵測到新版後，先儲存筆記的內文與標題，並等進行中的儲存與附件上傳完成，然後才出現更新視窗。
- **一律要更新**：更新視窗只有「立即更新」，沒有「稍後更新」與關閉按鈕，按 `Esc` 或點視窗外側都關不掉。新版下載失敗時會顯示原因，可以再按一次重試。
- **更新紀錄**：點左下角的版號，改為以視窗列出目前版本與先前各版本更新了什麼（原本是手動檢查更新）。內容隨介面一起下載，離線也能看。
- **選取文字後的右鍵**：電腦上選取文字後按右鍵，出現的是瀏覽器自己的選單（複製、查詢、翻譯等），不必再按 `Shift`。選取時的格式小選單照常自動出現。

## 範圍與限制

- 有些內容無法代為儲存：寫到一半還沒送出的留言、開著的欄位／視圖／排序設定、個人資料或密碼表單、正在編輯的資料格、尚未處理的衝突、輸入法組字中。這時更新視窗會等你完成或取消後才出現；左下角顯示「有新版」，點版號可以看到還在等什麼。
- 離線時更新視窗暫時不顯示，恢復連線後再出現，離線筆記不受影響。
- 沒有手動「檢查更新」了；仍會每分鐘、切回前景與恢復連線時自動檢查，打開更新紀錄時也會重查一次。
- 更新紀錄從 1.0.5 開始。
- 開了多個分頁時，每個分頁各自儲存、各自出現更新視窗。
- 格式小選單被關掉（例如按 `Esc`）而文字仍選取時，不能再用右鍵叫回來，重新選取即可。
- **強制更新從下一次升級開始生效**：這次從 1.1.6 以前升級，看到的仍是舊的更新視窗（可以稍後更新）；更新到 1.1.7 之後，再有新版時才是新的流程。

## 給維護者

- 更新資訊清單由 `src/server/releases.ts` 搬到 `src/shared/releases.ts`，伺服器的 `/api/version` 與介面的更新紀錄共用。之後發布要在這個檔新增更新資訊。`/api/version` 的回應格式與內容不變。

## 升級

升級前先使用線上備份：

```sh
docker compose exec app node dist/server/cli.js backup
git pull
docker compose up -d --build --wait
```

沒有 migration。已開啟的分頁會出現新版提示，更新後即可使用。
