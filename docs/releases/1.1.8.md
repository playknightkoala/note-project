# 1.1.8 — 資安與同步強化：共用頁面不被靜默覆蓋，登出與權限變更立即生效

這一版是一次全專案 code review 與資安加強審查之後的修正，由兩個審查者交叉複核。沒有新功能；修正集中在「共用頁面的同步」「登入與權限的生效時點」「伺服器讀取請求內容的方式」與部署設定。沒有資料庫 migration；移除了三個從未使用的依賴，其餘依賴版本不變。

## 變更

- **共用頁面不再被靜默覆蓋**：裝置上傳成功、但回應在半路遺失時會重送同一筆操作。若這段期間別人（共用頁面的成員或擁有者）已儲存新版，而你又繼續寫了新內容，現在會列為衝突讓你決定，不會把你的新內容直接蓋在對方的版本上；你沒有再寫新內容時，則直接顯示最新版本。
- **登出、停用與權限變更立即生效**：改密碼後，其他裝置的登入，以及當下還在傳送中的請求（包含用舊密碼登入、用舊密碼再改一次密碼）都會失效。帳號被停用、成員被移出共用名單或被改為唯讀之後，還在傳送中的修改、改名、留言與附件不會再寫入。
- **權限變更會同步到裝置**：共用的資料庫與資料列被改為唯讀後，裝置在下次同步就會得知（先前要等資料庫內容有變動）。
- **成員看不到未分享頁面的標題**：共用的頁面裡若「@ 提及」了沒有分享給對方的頁面，成員只會看到「無法存取這個頁面」。成員編輯並儲存後，擁有者看到的提及與標題不變。
- **密碼**：變更密碼時「目前密碼」每個帳號 15 分鐘最多輸入 5 次。密碼雜湊參數提高（scrypt p=1 → p=3），每位使用者下次登入時自動重算一次。
- **伺服器不再預先讀入請求內容**：確認登入與限流之後才開始讀取；未登入的請求不論送多少都不會佔用記憶體。同時處理的附件上傳以 4 個為限（每個帳號 2 個），其餘排隊，不會失敗。

## 範圍與限制

- 「重送後列為衝突」需要更新後的介面。仍停留在舊版介面的分頁在同樣情況下會收到衝突提示（即使沒有寫新內容），不會覆蓋別人的版本。
- 成員裝置上既有的共用資料庫，以及含有未分享頁面提及的共用頁面，更新後會重新下載一次。
- 提及的標題是盡力配對：同一個區塊裡對同一個頁面重複提及時，若成員刪掉前面那個或互換順序，擁有者看到的標題快照可能配到另一個。成員不會因此看到未分享頁面的標題。
- 登入與註冊的密碼運算時間約為先前的三倍。
- 這一版沒有在真實瀏覽器上逐項驗收衝突畫面與編輯器重新載入，這兩項由單元測試與 API 層測試涵蓋。

## 給維護者

- **HTTPS overlay（`compose.https.yaml`）**：
  - app 的連接埠固定只綁 `127.0.0.1`，`NOTES_BIND` 在 overlay 下不生效（app 已信任轉送標頭，不應能被直連）。
  - nginx 的錯誤輸出先經過濾程式才寫出：公開連結的 token 換成 `-`，含百分比編碼的網址整個不寫出。含中文檔名等編碼字元的請求在錯誤訊息裡看不到路徑，請對照存取紀錄。
  - 每個來源位址同時 100 條連線，超過回 429。
  - 需要支援 `!override` 標記的 Docker Compose（這一版以 v5.7.0 實測；太舊的版本會在讀取設定時報錯）。
- **新的選用設定**（預設都不限制）：`NOTES_MAX_ACCOUNT_STORAGE_MB` 限制每個帳號附件的總容量；`NOTES_MEMORY_LIMIT` 設定 app 容器的記憶體上限。
- **安全事件紀錄**：app 的紀錄新增登入成功與失敗、登出、變更密碼、管理者變更使用者、邀請碼建立與撤銷、分享設定變更。不含密碼、session、邀請碼與公開連結的 token，登入失敗也不記錄輸入的帳號欄位。
- **移除未使用的依賴**：`fflate`、`markdown-it`、`tar` 與 `@types/markdown-it`（已取消的 Joplin 匯入留下的，程式中沒有任何地方使用）。`import_jobs` 資料表與 `MAX_IMPORT_MB` 設定仍保留、未使用。
- 協定細節見 `docs/ARCHITECTURE.md` 的「授權時點與同步協定補充」，驗證紀錄見 `docs/VALIDATION.md`。

## 升級

升級前先使用線上備份：

```sh
docker compose exec app node dist/server/cli.js backup
git pull
docker compose up -d --build --wait
```

使用 HTTPS overlay 時照原本的方式加上 `-f compose.yaml -f compose.https.yaml`。沒有 migration。已開啟的分頁會先儲存再出現更新視窗，按「立即更新」後即可使用。
